## Source integration change

By explicit user direction during this iteration, the engine repository's seventeen isolated integration branches (`engine-mvp-source` through `engine-mvp-preview-worker`, tip `bcb9a029`) were merged into `main`. The previously uncommitted work on `main` was preserved first as commit `0375b05`, the chain merged as `4e41a89` (two hand-resolved conflicts in the CLI rating summary and the desktop deck store, both keeping both sides' intent), and the merged tree passed the full workspace gates before any new work. All worktrees were removed and the merged branches deleted. From this unit on, canonical engine work lands directly on `main`; the clean-clone qualification procedure in the source ADR is unchanged. The root `Cargo.lock` digest in the pin changed with that merge.

## Rules basis

From the pinned Comprehensive Rules corpus (SHA-256 `4381ad1b…`, effective 2026-08-07): CR 106.7 defines the type of mana a permanent "could produce" as what an ability would produce if it resolved at that time, ignoring costs; CR 601.2h pays the total cost during activation; CR 605.3b resolves an activated mana ability immediately after it is activated; CR 113.7a keeps an activated ability independent of its source. Together these fix the semantics: a contextual output domain is the one that exists after tap, sacrifice, selected and life costs are paid, and a source that sacrificed itself still resolves against the remaining lands.

## Architecture and reuse review

| Concern                       | Owner                                                       | Change                                                                                                                                                                                                                                                                                                                                                                                          |
| ----------------------------- | ----------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Grounded potential production | `mana/context.rs` fixed-point solver                        | `output_domain(state, controller, kind)` computes a controller's domain from the same solver without requiring the source on the battlefield; the pre-cost menu reuses it.                                                                                                                                                                                                                      |
| Activation costs              | `SourceCost`, `PhysicalPayment`, `pay_life`, `fee_payments` | Unchanged owners. `mana_output_options` prepares the physical witness and executes it on a private copy only for contextual abilities.                                                                                                                                                                                                                                                          |
| Output selection              | `mana/mana_ability.rs`                                      | Selections are semantic `ManaOutput` bundles. `activate_mana_output` is the new entry; `activate_mana_choice` and `activate_mana_choice_with_costs` keep their signatures but interpret the index against the recomputed post-cost domain, never a menu computed before a sacrifice moved its grounding land. `execute_activation` validates membership after payment on the transaction state. |
| Payment plans                 | `mana/payment.rs`                                           | `ManaActivation` carries the selected `ManaOutput` (`output()` replaces `output_index()`); exact search enumerates selected-cost choices, post-cost outputs and fee allocations through one `activation_options`. Plans remain bound to the exact state hash.                                                                                                                                   |
| Admission                     | `source_modes`                                              | The explicit rejection of contextual abilities with sacrifice or selected costs is removed; `mana_physical_cost_requests` now describes them.                                                                                                                                                                                                                                                   |

No worker protocol, snapshot schema, support registry, Oracle parser, TypeScript gameplay path or public MCP route changed. The only consumers of the index-based API were engine tests; `game_loop`, CLI, desktop and worker use `activate_mana_ability`, whose behavior for fixed sources is unchanged.

## Independent evidence

Canonical `tests/contextual_cost_output.rs` holds seven scenarios written before the implementation compiled: a selected sacrifice removing the only green provider (obsolete green rejected with byte-identical state and no events; index 0 resolves to the recomputed empty domain; the empty bundle pays with exactly tap, zone-change and activation events and no production event); a sacrificed control thief restoring a stolen Forest before output (empty bundle rejected, green produced); self-sacrifice for controlled land types and for opponents' land colors with exact event lists and the source in the graveyard; payment search that cannot plan `{G}` when the only creature is the green provider but plans `{C}` with the semantic colorless output, then plans `{G}` by sacrificing a non-land creature; a stale plan once the grounding land leaves; and a missing required selection rejecting without spending. A mutation that drops the post-cost membership check fails three of the seven. The former rejection test in `tests/selected_costs.rs` became an admission test.

Recorded gates on the merged main: workspace check, 1,630 tests (3 pre-existing skips), 109 doctests, strict Clippy with pedantic warnings denied, rustfmt; the 36 MCP-owned mana source fixtures remain green. Clean-clone identity checks before and after the locked offline arm64 release worker build, empty-directory self-check, contract sync/check, and 174 native MCP tests against the clean-clone binary are recorded on the pin task; MCP typecheck, tests and lint on the verification task.

## Boundaries and retained work

Zero-output contextual activations remain enumerable by the exact payment search, as before this unit; they can only matter when a sacrifice restores control of a land, and no scoring budget prunes them. Search cost grows with the number of selectable sacrifice objects on contextual sources; performance qualification stays with its roadmap owner. Commander identity, production replacement effects and exact Oracle clause bindings for Reflecting Pool, Exotic Orchard and similar cards remain with `engine-mvp-commander` and `engine-mvp-lands`. The unified decision surface (`engine-mvp-decisions`) can now close its contextual-output restriction; it still owes the remaining cost-choice, ward and expend integration.
