# Print image selector: one print-ready file per face

Accepted for `print-image-selector` under the [engine charter](../ENGINE-CHARTER.md). It is the third unit of the [Proxy Order Helper](print-order-helper.md) planned by the roadmap refresh `think:440`; the plan and grounding are `think:446` and the closing finding is recorded on the chunk. Native Magistr records hold execution status.

## What was delivered

`src/print/imageSelector.ts` exports `resolvePrintImages(input, deps)` and `defaultPrinting(card)`. It reads the manifest owner's faces and the job store's per-slot choices and writes into the job directory.

| Concern                | Behaviour                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Precedence per face    | The slot's recorded choice (the preset or an explicit prepare-time choice, as the job store merged them) wins; the back of a two-sided card takes the printing chosen for its front; otherwise the deterministic default printing; otherwise, when a community source is configured, a community image carrying exactly the face's name; otherwise an attention item                                                                                           |
| Default printing       | Newest `released_at`, then the alphabetically first set code, then the lowest collector number; printings without a release date sort last. Independent of catalog order, so stable for a given `data_snapshot`                                                                                                                                                                                                                                                |
| Never a different card | A chosen printing that is not among the card's printings is `printing_mismatch`; a community search with several exact-name images is `ambiguous_match` with the candidates and no download; a search with no exact-name image is `no_image`. Nothing is substituted                                                                                                                                                                                           |
| Scryfall               | `LiveScryfallClient.getCardImage(id, { face, version })` requests `/cards/:id?format=image&version=png[&face=back]` through the card-class throttle with the project User-Agent and `Accept: image/*`; 404 is `UNKNOWN_CARD`, other non-2xx (including 422 for a face the card lacks) is `UPSTREAM_UNAVAILABLE` with the status. Bytes are cached at `<job_dir>/cache/scryfall/<id>[-back].png`, so repeated copies and a re-prepare cost one request per face |
| Preparation            | `src/print/imagePrep.ts`: a catalog or community image is a trimmed card, so its transparent corners are flattened onto the border colour sampled just inside the edges, it is resampled (lanczos3, fill) to the 750 x 1050 trim and extended by 36 px per side with edge copy to 822 x 1122 PNG. An input already exactly 822 x 1122 passes through unchanged. EXIF orientation is honoured                                                                   |
| User files             | Copied as-is to the job directory after decoding and a dimension check against 822 x 1122 (`as_is`); smaller files are `undersized_image`, missing or undecodable files `unreadable_file`. A user file is treated as print-ready artwork because the selector cannot know whether it already carries bleed, and adding bleed twice would shrink the card                                                                                                       |
| Output                 | `<job_dir>/images/slot-<nnn>-front.<ext>`, `slot-<nnn>-back.png` and `card-back.<ext>`, written atomically (temporary file then rename). The job directory, cache and images directories are created with mode 0o700. The result carries, per slot, the prepared faces, the references actually chosen (defaults filled in, for the job record), the attention list and `complete`                                                                             |
| Degradation            | A failing face never fails the prepare: Scryfall outages are `source_unavailable`, community failures (transport, changed shape, non-image bytes) are `image_service_unavailable`, each for its face only; other faces still resolve                                                                                                                                                                                                                           |

`src/print/community.ts` exports the `CommunityImageSource` interface and `MpcAutofillCommunitySource`, which loads `2/sources/` once, posts the frontend's sanitised query to `3/editorSearch/`, hydrates identifiers through `2/cards/`, downloads through the anonymous Google Drive URL, and maps every failure and every unrecognised shape to `UPSTREAM_UNAVAILABLE`. Searches are cached per name within one resolve.

## Ownership and reuse review

- **One owner for "which image".** Only the selector decides a face's image. The job store keeps the choice vocabulary (`PrintImageRef`, now `printing | file | community`), the manifest keeps the faces, and the pending project file reads the selector's paths without re-deciding anything. The `print_*` tools (`print-mcp-tools`) will write the selector's `chosen` references back into the job so a reviewed order records the default that was used.
- **One Scryfall client.** `getCardImage` is a method on the existing live client, not a second client, so throttle, User-Agent, timeout and error mapping stay shared with the live card fallback in `src/index/fallback.ts`.
- **One place for the template.** The 822 x 1122 / 36 px constants, the dimension check and the preparation live in `imagePrep.ts`; the selector, the tests and the later project file read them from there.
- **Additive schema change.** The `community` image kind widens the job store's discriminated union; stored version-1 records still parse, and `imagesFromPreset` already treated any non-printing preference as front-only.
- **Dependency.** `sharp` is recorded with its footprint and install behaviour in [print-order-helper](print-order-helper.md); only `imagePrep.ts` imports it and `tsup` keeps it external.
- **Changed boundary.** The job store receipt said the project-file owner would create the job directory; the selector now creates it (0o700) because it writes first. The `print-project-file` record is updated accordingly; the setup doctor's `storage_permissions` list still learns `print-jobs` there.
- **Left for their owners.** Writing the selector's choices back into the job and the user-facing attention wording (`print-mcp-tools`); the project document and `cards.xml` (`print-project-file`); configuration of the community backend URL and the browser profile (`print-mcp-tools`, `print-mpc-filler`).
- **Overlap.** None added. No engine, catalog, deck-store or validator change.

## Evidence

Scenarios were written first and failed on the missing modules and the missing client method. `src/print/imagePrep.test.ts`: the template constants; a 745 x 1040 card-like PNG with transparent corners becomes 822 x 1122 with the border colour in all four bleed bands and the flattened corners, the card's own border just inside the cut and the inset content inside the safe area; an exact 822 x 1122 input passes through byte-identical; a white border yields white bleed; 488 x 680 and 1500 x 2100 inputs reach the template; non-image bytes are rejected. `src/ingest/live.test.ts`: the png URL, User-Agent and `Accept` header; `face=back` and `version`; the shared card throttle; 404 and 422 mapping. `src/print/community.test.ts` over recorded fixtures: sources loaded once, the editorSearch and cards request and response shapes, empty results without a cards request, outages, an unrecognised shape and an HTML download answer all as `UPSTREAM_UNAVAILABLE`. `src/print/imageSelector.test.ts`: default-printing ordering and independence from catalog order; one fetch per printing for repeated copies with the cache reused on a second resolve; a chosen printing over the default and a mismatched printing refused; a transform card's front and back from one printing; a user-file front with the catalog back; Scryfall miss, outage and 422 per face; cards without printings and unknown cards; user files as-is, undersized, missing and unreadable; the card back as file, printing and absent; community single match, explicit identifier, ambiguity, outage, non-image bytes and the unconfigured case.

Recorded gates: TypeScript typecheck; vitest for the print and live test files; ESLint and Prettier.
