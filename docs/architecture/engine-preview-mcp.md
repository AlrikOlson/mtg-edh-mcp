# Running and cancelling the internal fixture through real MCP

This receipt follows the [engine charter](../ENGINE-CHARTER.md), the [canonical source procedure](engine-source.md) and the [bounded worker receipt](engine-preview-worker.md). Native chunk `engine-mvp-preview-mcp` and think:344 record scope. The engine [source pin](../../engine/source.json) is unchanged at `bcb9a029` (protocol 5); no canonical Rust source or contract byte changed in this unit.

## Ownership and reuse

The canonical Rust core stays the sole owner of setup, legality, payments, priority, resolution, combat, terminal evaluation and execution control; the `mtg-worker` process stays the only executor. MCP retains catalog and construction authority: `capturePreviewFixture()` supplies the trusted fixture with no caller input, and `validateDeck` is untouched. The public `simulate_deck` route and the TypeScript analysis owners are untouched and still retire together at `engine-mvp-cutover`; nothing here is a fallback.

Three TypeScript owners were added over existing seams.

- `src/engine/trialSeed.ts` is the single owner of the worker's trial-seed derivation (SHA-256 over the fixed domain, the scenario seed and the big-endian trial index, first 16 hex digits). The worker rejects any other seed, so seeds stay independent of scheduling; the boundary test now imports this owner instead of a private copy.
- `src/engine/supervisor.ts` is the reusable asynchronous worker supervisor the charter requires: a fixed absolute executable and argument array (never a shell, never a protocol-selected path), an empty child environment, bounded LF framing through the existing `WorkerFrameDecoder`, continuously drained stdout and stderr, a concurrency ceiling (`busy`), a parent elapsed deadline, stdout and stderr byte ceilings, replies routed by `request_id` with any unrouted or malformed reply ending the session, cooperative `cancel` for the live run on abort followed by SIGTERM and SIGKILL after a grace period, and a receipt produced only after the process `close` event, so no run can leave an orphan. It interprets no game state. `engine-mvp-supervision` reuses it for durable jobs; memory ceilings remain there.
- `src/engine/previewRun.ts` is the injected shared service: one instance per process is passed through `createServer` to the pinned stdio server and to every per-request HTTP server, so all cross-request state lives outside `McpServer` instances and the preview needs no Tasks extension. Per request it validates a strict bounded input (fixed fixture id, 16-hex seed, trial index and count up to eight, the two named policies `fixture-baseline@1` and `fixture-pass@1`, turn/action/per-turn/work/elapsed/output ceilings), deep-freezes the protocol-5 `Admission`, spawns exactly one worker, performs the handshake, admits, runs one trial with the derived seed, keeps a bounded 64-event progress trace with the total count, and returns the worker's own outcome (`completed`, `truncated`, `cancelled`, `unsupported`, `invalid` or `engine_error`) with versions, digests, limits and the process receipt. An admission refusal is returned as stage `admit` with the worker's diagnostic; a supervisor failure is a typed error, never a game result.

`src/server/engineTools.ts` exposes `engine_preview_fixture` only when `MTG_ENGINE_PREVIEW=1` names an executable through `MTG_WORKER_BINARY` (checked absolute and executable at boot). The tool uses the installed SDK's ordinary `tools/call` context: `mcpReq.signal` cancels the worker (cooperatively first, then by force), `mcpReq._meta.progressToken` and `mcpReq.notify` emit `notifications/progress` per completed turn, and the description declares the numeric maximum duration (36,000 ms: the 30,000 ms worker budget ceiling, 5,000 ms parent grace and 1,000 ms kill grace) regardless of progress. Unknown argument keys are refused through a new `strictInput` registry option rather than stripped, because an extra `deck_id` or profile is a request for something this route never does. A supervisor failure surfaces as `UPSTREAM_UNAVAILABLE` with `details.reason`; an inconsistent input as `ENGINE_PREVIEW_INPUT`.

## SDK finding and shim

The installed `@modelcontextprotocol/server` 2.0.0 aborts a handler's signal on transport close and on `notifications/cancelled`, but its notification handler drops JSON-RPC request id 0 (`if (!requestId) return`). On a modern (2026-07-28) stdio connection the client's first request carries id 0, so the first `tools/call` could never be cancelled. A wire trace confirmed the client sends the notification and a probe handler confirmed the server never aborted. `src/server/registry.ts` now keeps a per-server map of abort controllers keyed by request id, hands every tool handler `AbortSignal.any([sdkSignal, own])` and registers its own `notifications/cancelled` handler that aborts for any id. This replaces the SDK handler only for tool calls, which all pass through the registry; no other request handler in this server consumes a signal. The stdio acceptance test pins first-request cancellation so the shim can be retired when the SDK honors id 0. Streamable HTTP cancellation is the client closing the request stream, which the `@modelcontextprotocol/node` adapter turns into the same abort.

## Independent evidence

`src/engine/supervisor.test.ts` drives the real supervisor against a real `node -e` fake worker that speaks protocol 5 (`src/engine/fakeWorker.test-support.ts`): clean close with routed replies; a hung worker killed at the parent deadline with SIGTERM; SIGKILL escalation when SIGTERM is ignored; a crash reported with its exit code; malformed and unrequested replies ending the session; stdout and stderr floods terminated at their ceilings; abort before spawn, cooperative cancel honored by the worker, an ignored cancel hard-killed after the grace, abort with no live run, busy refusal beyond the concurrency ceiling, an early clean exit reported as crashed, and a missing executable reported as `spawn_failed`; every case checks the process is gone afterwards.

`src/engine/previewRun.test.ts` covers the input boundary (undeclared fixture, seed, deck id, policy and limits refused; trial index at or beyond the count refused before spawn), the fake worker (completed report with frozen inputs, `unsupported` and `engine_error` returned as results, crash as a worker failure, cooperative cancel, hard kill, busy) and the pinned native worker: the baseline beats the passing client by a lethal attack on turn five with four progress events, two processes agree on admission, outcome and events byte for byte, a turn cap answers `truncated/turn_limit` with no winner, and a second trial index changes the derived seed under the same scenario digest. The admission hash proves setup for the scenario seed; the trial starts from its derived seed.

`src/server/engineTools.test.ts` uses real clients over real transports: the tool is absent by default and present only with an injected service; over stateless Streamable HTTP a modern client receives `unsupported` and `engine_error` as stamped results, a crash as `UPSTREAM_UNAVAILABLE`, refusals for every undeclared input before any worker starts, progress notifications and a completed result; a legacy 2024-11-05 client is still served; closing the HTTP request mid-run stops the worker (hello, admit, run and cancel recorded, exit 0, no hard kill, no live worker afterwards); and `ping` from a second client answers well within two seconds while a run is live. Over a real stdio server process, a run completes and a `notifications/cancelled` for request id 0 stops the worker. Against the pinned native worker, HTTP shows the turn-five victory with four progress notifications, stdio reproduces the same admission, outcome, events, catalog digest and trial seed as HTTP, and the turn cap truncates.

Recorded gates: the configured TypeScript, test and lint gates through `magistr_gate`; the engine and server suites additionally ran with `MTG_WORKER_BINARY` pointing at the clean-clone worker from `engine-mvp-preview-worker`. The native cases skip when that variable is absent, exactly like the existing boundary tests.

## Limits

Only the immutable two-seat internal fixture runs; there is no authored-deck, Commander, Muldrotha or four-seat claim. Memory ceilings are declared to the worker but enforced by neither side until `engine-mvp-supervision`, which also owns durable background jobs, queueing beyond the busy refusal and the Tasks extension. Hidden-information scoping remains the named clients' discipline (`engine-any-policy-observations`); the baseline never blocks or searches (`engine-mvp-policies`). A cancellation observed by the client is a rejected call; the worker's `cancelled` outcome is visible only through the service receipt, not the MCP response, because the specification tells clients to ignore responses to cancelled requests. The route is internal until `engine-mvp-cutover`, when the fixture becomes a conformance harness and the supervisor and service serve the public simulation owner.

Primary references: the [MCP 2026-07-28 cancellation contract](https://modelcontextprotocol.io/specification/2026-07-28/basic/patterns/cancellation) (stdio `notifications/cancelled`, HTTP stream close, timeout and race requirements), the [MCP tools specification](https://modelcontextprotocol.io/specification/2026-07-28/server/tools) (no duration field on a tool, hence the declared description), and the [Node child-process documentation](https://nodejs.org/api/child_process.html) for `spawn`, `kill` and the `close` event.
